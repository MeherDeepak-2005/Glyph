## Frequency evidence and limits

38,548 additions occur in the available human-source inputs. The remaining 34,626
are spelling-source forms without measured human usage in these inputs, and receive
explicit smoothing. Their frequency is not presented as an observed count.

The estimator uses exact FrequencyWords 2018 subtitle counts and the project's
deduplicated Tatoeba/WikiText training counts. It selects a 20%/60%/20% source mixture
from a fixed 66-point grid using validation likelihood for words outside the neural
output vocabulary. SODA's synthetic dialogue counts are recorded for audit only and
do not affect admission, fitting or probabilities. Stored integer weights are
quantized probability estimates on a one-billion-unit scale, plus the runtime's
one-unit smoothing; they are not raw corpus counts.

The spelling backbone is the pinned American-English ESDB 60/70 snapshot. That
historical snapshot folds source casing and accents. Existing Indian, British and
other regional spellings remain from the baseline. This does not constitute a new
Indian-English frequency survey or independent native-speaker review. The source
data also does not establish contemporary human-chat/Gen Z usage rates.
See [source notices](../../tools/data/nss/unigram-v1/NOTICE.txt).

## Neural-only execution and bundling

The 9,254,997-byte KBLM v6 pack has **zero bigrams, trigrams, starter rows and phrase
contexts**. Its 568-byte sidecar only preserves approved spellings and prevents
automatic replacement with protected slang. It does not boost suggestions.

The CIFG model and its 30,000-word vocabulary/output pairing are unchanged.
Extra lexicon words use the existing neural unknown-word distribution and unigram
allocation. The extension retains its existing unigram floor setting.

The extension build now selects this pack through NSS_DICTIONARY_DIR in
Config/Extension.xcconfig. The installer owns the bundled langdata.bin and
langdata.kbmodern outputs, verifies checksums and the paired CIFG model, and rejects
missing/mismatched inputs. It does not package the old large n-gram dictionary.
The source keyboard/langdata.bin remains a historical reference for reproducible
comparisons and rollback, rather than the production resource selected by this build.

EngineOptions.nssOnly enforces raw neural decoding, neural unknown-literal scoring,
and rejection of an n-gram tier. It bypasses the older phrase/prefix display boosts.
Swift preserves typed input if the configured neural model cannot load or decode,
instead of switching scorers. Glide's shared NSS path uses neural scores for dynamic
words; legacy scoring paths are refused when NSS is configured.

## Evaluation

A fixed 3,238-case sample from 652 held-out Tatoeba/WikiText documents was generated
without dictionary-dependent target selection. Both runs used the same CIFG model,
channel, safety data, preservation policy and neural-only options. Test data did not
select the unigram mixture. Errors are synthetic; this is not a blind evaluation of
the already-trained neural model or a user typing study.

| Measure | Previous unigram weights | New unigram weights |
|---|---:|---:|
| Prefix completion top three | 541/652 (82.98%) | 544/652 (83.44%) |
| Deletion typo top three | 596/652 | 598/652 |
| Transposition typo top three | 612/630 | 614/630 |
| False correction of correct input | 15/652 | 10/652 |
| Next-word top three | 155/652 | 155/652 |

The paired bootstrap intervals for suggestion gains include zero. These are modest
observed improvements, not a claim of statistically established population gains.

Lexical token coverage rises from 98.642% to 98.789% on Tatoeba and from 96.163% to
96.671% on WikiText. On neural-OOV tokens supported by both packs, conditional
negative log likelihood improves from 11.527 to 10.305 and from 12.201 to 10.617
respectively (lower is better). Coverage and likelihood are separate from typing
accuracy.

Native tests verify exact neural probabilities, unigram allocation, lookahead and
top-candidate search on the expanded pack. Python tests verify list completeness,
count/probability consistency, checksums, model pairing, empty n-gram tables and
installer failure behavior. Full device latency/memory and complete signed-extension
release budgets remain unverified; see validation-status.json for current build results.

## Reproduction

From the repository root, with the existing pinned source cache available:

~~~sh
python3 -B tools/vocabulary/build_unigram.py
python3 -B -m unittest tools.vocabulary.test_unigram
python3 -B tools/evaluation/autocorrect/evaluate.py build --bin unigram-v1
python3 -B tools/vocabulary/evaluate_unigram.py
cmake -S native -B /tmp/keyboard-unigram-native -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/keyboard-unigram-native
ctest --test-dir /tmp/keyboard-unigram-native --output-on-failure
~~~

The cached training counts and split database come from
tools/nss/rigorous_2026_11_02/corpus.py; their hashes and limitations are in the build
manifest. Dictionary builds do not retrain the CIFG model or run recurring automation.
